# Timer1-1Hz-Generator
본 프로젝트는 ATmega328P의 16비트 하드웨어 타이머를 활용하여, 메인 루프의 간섭이나 소프트웨어 딜레이 없이 하드웨어적으로 정확한 1초(1Hz) 타임 베이스를 생성하는 프로젝트입니다.
단순히 delay() 함수로 시간을 때우는 것이 아니라, 16MHz 시스템 클럭을 Prescaler하고 비교 매치 레지스터를 정밀하게 계산하여, CPU 자원을 낭비하지 않는 인터럽트 기반의 실시간 시스템을 밑바닥부터 설계했습니다.
TP1637 protocol은 제 github self-protocol-tp1637에 정리되어 있어 거기서 확인하시면 됩니다.

## Project Overview
1. 16비트 타이머(Timer1)의 정밀 설계
  8비트 타이머의 한계를 넘어, 그릇이 큰 16비트 타이머(Timer1)를 사용하여 단 한 번의 하드웨어 사이클로 1초를 구현했습니다.
  분주비(Prescaler) 1024: 16MHz 클럭을 1024로 나누어 타이머에 공급함으로써, 1초를 15,625라는 카운트 값으로 변환했습니다.
  CTC 모드: 목표 카운트 값(15,624)에 도달하는 순간 타이머를 자동으로 0으로 리셋시키며 인터럽트를 발생시키도록 하여, 시간 오차를 원천 차단했습니다.
2. 인터럽트 기반의 비차단 구조
  메인 루프가 디스플레이 통신을 위해 멈춰있지 않도록 설계했습니다.
  하드웨어 인터럽트(ISR): 1초마다 타이머가 CPU를 노크하면, ISR 내에서 값만 증가시키고 즉시 복귀합니다.  
  플래그(Flag) 동기화: ISR은 update_flag를 던져주기만 하고, 통신 작업은 메인 루프가 처리하게 함으로써 메인 루프의 자원 활용도를 극대화했습니다.

## 회로도 분석

1. **하드웨어 카운팅 (TCNT1):** 16MHz 시스템 클럭(`clk_I/O`)이 프리스케일러(1024분주)를 거쳐 `clk_T1`이 됩니다. 이 신호가 `Control logic` 에 입력되면, CPU가 관여하지 않아도 물리적인 게이트를 통해 하드웨어적으로 `+1` 연산이 수행됩니다.

2. **비교기를 통한 즉각적 반응:** `TCNT1`에 입력된 값은 항상 하드웨어 비교기(`=`)를 통해 `OCR1A` 레지스터와 실시간으로 비교됩니다. 소프트웨어 루프와 상관없이 `TCNT1 == OCR1A`가 성립하는 그 순간, 비교기에서 하드웨어 신호가 발생합니다.

3. **CPU 부하 최소화 (인터럽트 구조):** 비교 일치 신호는 `TIFR1` 레지스터의 `OCF1A` 플래그를 세우고, `TIMSK1` 마스크가 활성화되어 있다면 즉시 CPU에 인터럽트 요청을 보냅니다. 
   - 이 과정을 통해 **CPU는 매 클럭마다 타이머를 감시할 필요가 없습니다.**
   - 오직 1초에 한 번, 인터럽트가 발생했을 때만 ISR 루틴으로 점프하여 카운트 값을 갱신하고 메인 루프에 알림을 보내도록 설계했습니다.

4. **왜 15624인가? (타이밍 수학적 근거):**
   - $f_{clk} = 16,000,000 \text{ Hz}$
   - $f_{timer} = f_{clk} / 1024 = 15,625 \text{ Hz}$
   - $OCR1A = (15,625 \times 1\text{sec}) - 1 = 15,624$
   
   이 계산을 통해 하드웨어 타이머는 완벽하게 1Hz의 주기성을 갖게 되며, 소프트웨어 오차를 원천 차단했습니다.

  
## 배운점

1. 동기화: 인터럽트 서비스 루틴(ISR)은 최대한 짧고 간결하게 유지하고, 무거운 통신 함수(tm1637_display)는 메인 루프로 분리하는 설계가 시스템 전체의 안정성을 얼마나 높이는지 체감했습니다.
